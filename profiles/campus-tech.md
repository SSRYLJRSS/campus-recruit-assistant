# 工作流档：校招·技术岗（campus-tech）

> 适用于研发/算法/测试/运维/数据等技术岗校招。
> 本档覆盖 `references` 默认值；未列出的项仍按默认执行。

## 结构（与通用档的差异）

| 项 | 本档规定 | 与默认档的差异 |
|---|---|---|
| 头部 | 三行：姓名 / 电话+邮箱 / 学校+专业+**届别** | ✅ 允许写届别（技术岗筛简历按届别卡） |
| 求职意向 | **可写一行**（细分方向明确时，如「后端开发工程师」） | ✅ 默认不写，本档允许 |
| 技能段 | **保留独立技能段**（语言/框架/工具/证书分四档） | ✅ 默认无技能段 |
| 段落 | 技能段 → 项目经历 → 实习经历 → 自我评价 | ✅ 项目优先于实习（技术岗看作品） |
| 页数 | **1-2 页**（有开源项目/论文可到 2 页） | ✅ 默认 1 页 |
| 小标题 | 项目写 `日期 项目名（角色）——技术栈` | ✅ 默认不含技术栈 |

## 技能段四档（本档唯一使用四档的地方）

| 档位 | 定义 |
|---|---|
| 精通 | 能独立解决复杂问题，有主导成果佐证 |
| 熟练 | 能独立完成常规任务，有项目佐证 |
| 熟悉 | 简单任务可完成，复杂需查资料 |
| 了解 | 仅接触概念 |

- 数量 6-12 项；文字描述，**不用星级/百分比**
- 没实际写过的技术不许标"熟练"（面试必被追问）

## 项目写法

- 必含：**技术选型理由** + **你负责的模块** + **量化结果**（QPS/延迟/体积/覆盖率/用户数）
- 开源项目要给：仓库地址、star 数、你的角色、核心 commit 做了什么
- 禁止只列技术栈名词（"使用 Spring Boot + Redis + MySQL"= 零信息）
- 篇幅不够时砍"职责描述"，保"技术决策 + 结果"

## 自我评价

- 一段话、不分点、字数**同默认档**（见 `references/16-自我评价.md`，本档不覆盖）
- 与通用档差异：第二句改为「技术纵深 + 解决过的最硬技术问题」，可提技术栈但必须带结果
- 不写"热爱技术""学习能力强"（无证据 = 空话）

## 面试重点

- 双人设改为：**技术深挖面**（追问原理/边界/替代方案）+ **项目盘问面**（你的贡献边界）
- 题库必加：**手撕代码 / 系统设计 / 项目深挖三层（做什么→为什么这么做→换个约束怎么办）**
- 群面通常不适用（部分大厂管培技术线除外）
- 高频命门：项目是不是你做的（追问 commit 细节）、技术选型能否说清权衡

## 与默认值的差异汇总

1. 允许届别行、求职意向行、独立技能段
2. 项目经历排在实习之前
3. 页数放宽到 2 页
4. 小标题允许带技术栈
5. 面试人格改为技术面/项目盘问面
