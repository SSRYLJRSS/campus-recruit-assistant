# 命名与版本规范

> 用途：[面试] 数据层文件的统一命名与版本管理，防覆盖、可追溯。
> 与 简历阶段规范同构（时间戳 `YYYYMMDD`；同名多版加 `_v2` 不覆盖）。

## 一、目录与文件命名

| 目录（数据层） | 文件命名 | 示例 |
|---|---|---|
| `[面试]\情报\` | `情报_公司_岗位_YYYYMMDD.md` | `情报_星屿传媒_新媒体运营_20260802.md` |
| `01_JD库\` | `JD分析_公司_岗位_YYYYMMDD.md` | `JD分析_星屿传媒_新媒体运营_20260802.md` |
| `[面试]\题库\` | `题库_公司_岗位_YYYYMMDD.md` | `题库_星屿传媒_新媒体运营_20260802.md` |
| `[面试]\记录\` | `面试_公司_岗位_YYYYMMDD_人设.md` | `面试_星屿传媒_新媒体运营_20260802_压力面.md` |
| `[面试]\薄弱点库.md` | 固定单文件，追加不覆盖 | — |
| `[面试]\讲稿\` | `讲稿_公司_岗位_YYYYMMDD.md` | `讲稿_星屿传媒_新媒体运营_20260802.md` |

规则：
- 公司/岗位用中文，无空格；未知公司/岗位用 `未知公司` / `未知岗位`。
- 同一公司同岗位同日多次模拟：人名后缀 `_压力面` / `_普通面` 区分；仍冲突加 `_v2`。
- 复盘报告**追加在同一面试记录文件内**（实录在前、复盘在后），不单独成文件。

## 二、版本规则

- **不覆盖**：同日/同名新文件一律新文件或 `_v2`，永不覆盖旧版。
- **情报库同岗复用**：同岗二次面试，情报文件可被新面试引用（旧文件不动），新情报追加新文件。
- **情报过期规则**：情报文件头部标「有效截止 YYYY-MM-DD」（与抓取日期同为日粒度 YYYY-MM-DD）；同岗复用超 3 个月必须重搜校验，未校验的旧情报标注「已过期，仅参考」。
- **JD 分析复用**：`01_JD库\` 的轻量分析同岗直接复用；回填 定制阶段 存档前文件头保持「轻量版」标注。
- **题库演进**：同岗二次面试出「题库_v2」或增量题单（沿用旧题库 + 新题），旧题库保留。

## 三、文件内部格式要求

- 每文件开头头部块：日期 / 公司 / 岗位 / 人设（面试记录）/ 数据来源（情报库：来源清单；题库：出处映射）。
- 面试记录：`## 实录` 分段（按 Q1/Q2 序号），复盘报告从 `## 复盘报告` 开始。
- 情报库每条：`结论 | 来源 | 日期（抓取日 YYYY-MM-DD）| 置信度 | 使用禁区` **五要素缺一不可**；无来源（URL）的结论不写入。使用禁区固定写：仅公开信息参考、不臆造、不外传、不推测未公开薪资 / 未证实的负面。
- **置信度取值口径（可执行）**：以「该结论的独立来源数」为分母（同一内容多站转载只算 1 个来源）——**HIGH**：印证来源占比 ≥50%；**MEDIUM**：25–49%；**LOW**：<25% 或仅单源；**GAP**：未搜集到 / 抓取失败。用户独家面经按「用户输入」记来源，单源最多标 LOW 并注「单源待验证」，不因单源丢弃（用户补充优先）。

## 四、变更记录

- 规则改动：在 `references/01-口径总表.md` 追加或修订一行（日期 + 改动 + 原因），旧规则直接删除不保留。
- 数据层大改（如薄弱点库重建、目录调整）：在 `[面试]\薄弱点库.md` 或对应目录记变更说明。
- 回写 [档案] 母版：走 简历阶段的 `[档案]\变更记录.md`，面试阶段不另立记录。

## 五、与 简历阶段的命名边界

- 面试阶段产出**不占用** 简历阶段命名空间（`CV_` 前缀文件、`JD_` 前缀文件、`[JDK]` 均归 简历阶段）。
- 面试阶段复用定制阶段文件时**只读**，写入一律进 [面试] 数据层；回写走确认 + 变更记录流程。
