# 匹配评分规则

> 说明：本文出现的公司名、机构名、项目名均为**化名**（不指向任何真实主体），数值为示例值；仅示范"选材与迁移"的思考方式，实际内容一律从 `[档案]` 取，**不照抄、不借用**。

> 用途：S1 对 JD 与母版做匹配打分，产出投递决策依据 + 定制优先级。
> 数据源：数据层 `[档案]\`（母版）、`[JDK]\`（JD 结构化分析）
> 参考：yanliudesign/job-description-skill（match-rubric）、proficiently-claude-skills（fit-scoring）、Paramchoudhary/ResumeSkills
> 原则：**分数必须可复现**——每个分值都要能说出依据（哪条经历、哪个数字）。禁止拍脑袋整体打分。

## 目录

- 一、打分顺序（固定，不跳步）
- 二、缺口清单（配合决策输出）
- 三、打分示范（用示例母版走一遍）
- 四、常见坑

## 〇、Step 0 母版就绪检查（先做，空库拒绝打分）

- **检查**：`[档案]\` 存在，且母版各模块非空（至少教育背景 + 1 段实习/项目）。
- **不通过**（档案不存在或为空）：**不要打分**，直接回 S0 建库——否则空库会让所有必须项=0，把「没建库」误判成「不合格 / 建议跳过」。先说明缺什么，按 `00-首次使用与配置.md` 的 A/B 路径建库。

## 一、打分顺序（固定，不跳步）

```
① Dealbreaker 检查（一票否决） → ② 必须项打分 → ③ 加分项打分 → ④ 隐藏信号打分 → ⑤ 汇总+区间 → ⑥ 投递决策
```

### ① Dealbreaker 检查（先做，命中即止）

JD 分析里标注的硬性门槛，任一不满足 → 直接 **Skip**，不再打分：

| 门槛类型 | 示例 | 判定 |
|---|---|---|
| 学历 | 硕士及以上 | 母版本科 → 不满足 |
| 证书/资质 | 必须持某证 | 母版没有 → 不满足 |
| 硬性年限 | 3 年以上经验（校招一般无此条） | 应届 → 视 JD 是否注明可放宽 |
| 地区 | 必须驻某地 | 现居不符且无法到岗 → 不满足 |
| 身份 | 仅限 25 届/26 届 | 应届身份不符 → 不满足 |

- 判定规则：JD 出现「必须/要求/仅限/硬性」且没有「优秀者可放宽」字样 → 按门槛处理。
- 结果：Skip 也要产出说明（哪条门槛不满足），交给用户决定是否仍要投（用户明确要求则继续，标记「用户知情」）。

### ② 必须项打分（MustHave）

把 JD 必须项逐条与母版比对，单条三档：

| 档位 | 分值 | 判定标准 |
|---|---|---|
| 完全命中 | 1.0 | 母版有**直接对应**的经历/技能 + 能量化 + 时间近 |
| 部分命中 | 0.5 | 相邻领域可迁移 / 有经历但缺数字 / 角色非核心 |
| 未命中 | 0.0 | 母版没体现（**简历没体现 = 0 分**，不靠口述脑补） |

**技能类要求的判档**（JD 未注明熟练度时）：母版「熟练/精通」→ 1.0；「入门」→ 0.5（如实标注，不升格）。JD 注明熟练度要求的，按母版是否达标判定。

**复合要求判档**（如「教育行业+内容经验」这类二合一要求）：按**最弱组件**判定——行业命中但内容属性缺失 → 0.5；两部分都缺 → 0.0。

```
MustHaveScore = Σ(每条必须项得分) / 必须项总条数
（必须项 0 条时按 1.0 计，报告里标注「JD 无必须项」）
```

### ③ 加分项打分（NiceToHave）

同上三档，逐条打分后取平均：

```
NiceToHaveScore = Σ(每条加分项得分) / 加分项总条数
（加分项 0 条时按 0.5 中性计，报告里标注）
```

### ④ 隐藏信号打分（HiddenSignal）

从 JD 里挑 3-5 个最强的软性信号（ownership / 自驱 / 抗压 / 结果导向 / 跨团队协作…），逐条 0 / 0.5 / 1：

| 信号 | 母版表现 | 分值 |
|---|---|---|
| ownership / 主导 | 经历里有「独立负责/从0搭建/主导」类表述 | 1.0 |
| 抗压 / 快节奏 | 有高产/多线并行/大促期等数字 | 1.0 |
| 协作 | 有跨岗协作经历 | 1.0 |
| 中性 / 看不出 | — | 0.5 |
| 反信号（明显不符） | 与信号相反的表述 | 0.0 |

```
HiddenSignalFit = Σ(选中信号得分) / 信号条数
（信号 0 条时按 0.5 中性计）
```

### ⑤ 汇总公式与惩罚

```
匹配分 = 0.6 × MustHaveScore + 0.2 × NiceToHaveScore + 0.2 × HiddenSignalFit
```

惩罚规则（必须项不达标直接压分，防止「加分项好但硬伤」的假高分）：

| 情形 | 总分上限 |
|---|---|
| 任一条必须项 = 0 | 封顶 75% |
| 两条及以上必须项 = 0 | 封顶 55% |
| 门槛型必须项不命中 | 硬门槛（JD 写「必须/仅限」）→ 走 ① Dealbreaker 直接 Skip；软门槛（「优先/倾向」）→ 直接 25-35% |

**输出区间，不给单点**：同一份 JD 不同人翻译有判断差异，合理宽度 ±5-8 个百分点。

```
匹配度 = 72-80%（中高）
```

并附定性档与依据表（每条分数 → 母版哪条经历/哪个数字）。

### ⑥ 投递决策（以区间**中值**为决策分；区间下限 <50% 时强制跳过）

| 区间中值 | 决策 |
|---|---|
| ≥ 70% | 值得深投：完整定制（S2 全流程） |
| 50-70% | 可投但提示缺口：定制 + 向用户列出缺口清单，由用户拍板 |
| < 50% | 建议跳过（用户坚持则投，标注缺口） |
| 有 Dealbreaker | Skip（除非用户知情后仍要求） |

> 示例：匹配度 72-80%，中值 76% → 深投。若区间为 45-52%（中值 48.5% 但下限 <50%）→ 强制跳过。

## 二、缺口清单（配合决策输出）

- 逐条列出「JD 要求但母版缺失/薄弱」的能力项。
- 每条缺口给**补法**：回母版挖掘可补（有隐性经历没入库）→ 先补库再定制；确实没有 → 如实放弃该项，不编造。
- 缺口清单写进定制说明，用户可据此决定是否补材料。

## 三、打分示范（用示例母版走一遍）

> 假设 JD（新媒体运营）：必须项 = ①内容创作能力 ②数据复盘习惯 ③AI 工具使用；加分项 = ①视频剪辑 ②多账号运营；隐藏信号 = 自驱 / 结果导向。

| 项 | 打分 | 依据（母版） |
|---|---|---|
| 必须①内容创作 | 1.0 | 经历01：月产 10+ 篇百万播放文案（新媒体/内容标签命中） |
| 必须②数据复盘 | 1.0 | 经历01：日常视频数据复盘、驱动选题迭代 |
| 必须③AI 工具 | 1.0 | 经历01：AI 工作流/自研 Agent 工作流提效 100%+ |
| 加分①视频剪辑 | 0.5 | 经历01：必要时亲自上手剪辑（非主力） |
| 加分②多账号运营 | 1.0 | 经历02：衡广文化多账号 |
| 隐藏①自驱 | 1.0 | 经历01：独立搭建 Agent 工作流并推广 |
| 隐藏②结果导向 | 1.0 | 全库大量量化结果 |

```
MustHave = 3/3 = 1.0；Nice = 1.5/2 = 0.75；Hidden = 2/2 = 1.0
匹配分 = 0.6×1.0 + 0.2×0.75 + 0.2×1.0 = 0.95 → 输出「88-95%，高」（±约 5-7 个百分点）
```

> 注：示例仅为演示打分过程；实际分数以真实 JD 分析为准。

## 四、常见坑

- 打分前不先看 Dealbreaker → 白算一遍。
- 「我觉得差不多」式整体打分 → 违规，必须逐条给依据。
- 用口述/想象补母版缺口 → 违规，缺口走「补库 or 放弃」。
- 输出单点数字（如 78%）→ 违规，必须给区间。
