# 面试准备 SOP 总览

> 任务三：输入岗位画像 → 行业情报 → 定制题库 → 模拟面试（压力面/普通面）→ 复盘 → 演进
> 数据源：简历阶段 母版 `[档案]\`（唯一事实源）+ 定制阶段 JD 分析存档 `[JDK]\`（优先复用）
> 数据层（本任务）：`面试阶段\`
> 本文件是通用方法，不绑定任何个人路径与身份。
> 配套文件：22-人设卡.md / 21-出题规则.md / 23-复盘规则.md / 24-群面与AI面.md / 25-面试命名.md

## 核心原则（优先级从高到低，冲突时按此裁决）

1. **准确性**：所有问题从真实经历/JD 派生，绝不编造用户没做过的事、没写进母版的事实。
2. **用户纠正**：用户喊停、纠正、换人设 > 一切面试官行为。面试官人格只作用于「面试中」，复盘时回归教练人格。
3. **真实优先**：面试官问的问题，用户必须能用自己的真实经历回答；答不出 = 暴露缺口，不是面试官出题失误。
4. **不泛化套题**：禁止用「任何岗位都能问」的通用问题糊弄，每题必须能追溯到母版经历 / JD 条目 / 情报条目。
5. **角色严格切换**：面试中不提示、不递答案、不评价（压力面更甚）；所有反馈留到复盘阶段。

## 面试流程（6 步，每步有输入/动作/产出/验收）

### Step 0：前置检查（弹药就绪性）

- **检查**：[档案] 母版各模块存在且含目标岗位方向弹药；定制阶段 JD 分析存档有目标 JD（或本次现场分析）；行业情报库非空（或本次现场搜集）。
- **不通过**：先回 简历阶段 补齐，禁止带盲区面试。
- **产出**：一句话就绪确认（记入面试记录开头）。

### Step 1：输入定位（岗位画像）

- **优先**：读取 定制阶段 `[JDK]\JD_公司_岗位_日期.md`——职责/必须项/加分项/关键词/隐藏信号/dealbreaker 直接用。
- **没有存档**：做轻量 JD 分析（对照 定制阶段 的 `01_JD分析模板.md`，至少提取：岗位名称、职责 3-5 条、必须项、关键词、隐藏信号 3-5 个），**结果按同构格式存入 JD 库 `01_JD库\JD分析_公司_岗位_YYYYMMDD.md`**，文件头标注「轻量版，建议回填 定制阶段 存档」。同岗二次面试直接复用，不重复分析。
- **产出**：岗位画像（一句话 + 5 维度清单）。

### Step 2：行业情报搜集（对应外部 interview-skill 的 Research Engine，简化为 3 层）

> 目的：让面试官问得出「行业/公司/岗位」层面的题，用户答得出「你对这个行业怎么看」。

**执行方式（防造假铁律）**：① **优先用 WebSearch 执行搜索**（搜索聚合页 → 提取候选链接）；`curl` 仅作备用，且必须处理 0 字节 / 乱码，失败立即改走 WebSearch，**不在死路重试**；② 对候选链接逐条抓取正文、提取结论；③ 抓取失败 / 仅单源无印证 → 该条置 **GAP**；④ **禁止用 LLM 自产内容冒充搜索结果**；⑤ 写入情报文件的每条结论必须带**真实 URL + 抓取日期**，无 URL 不落盘。

1. **L1 多维搜索**：生成 5-10 个精准 query，覆盖 5 维度：
   | 维度 | 目标 | 示例 query（新媒体运营） |
   |---|---|---|
   | 公司基本面 | 业务/规模/账号矩阵/发展阶段 | 「{公司} 新媒体 业务 矩阵」 |
   | 岗位方法论 | 该岗位的核心指标/常用工具/考核口径 | 「新媒体运营 KPI 指标 2026」 |
   | 行业趋势 | 平台政策/内容趋势/热点玩法 | 「2026 短视频行业趋势 内容运营」 |
   | 面经/真题 | 该公司/岗位常问什么 | 「{公司} 新媒体运营 面试 面经」 |
   | 近期动态 | 产品/招聘/负面 | 「{公司} 2026 动态」 |
2. **L2 评分过滤**：每条结果按 时效性(0.3) + 来源可信度(0.4) + 相关性(0.3) 打分，综合分 <2.5 丢弃；记录丢弃数（透明）。
3. **L3 交叉验证 + 置信度**：跨来源聚类统计，按 `25-面试命名.md` §三「置信度取值」口径标注 **HIGH / MEDIUM / LOW / GAP**（以独立来源数计，同一内容多站转载只算 1 个来源）。
- **产出**：`[面试]\情报\情报_公司_岗位_YYYYMMDD.md`（每条：结论 + 来源 + 日期 + 置信度 + **使用禁区**）。**使用禁区**固定写清：仅作公开信息参考、**不臆造**未公开内容、**不外传**、**不推测**未公开薪资 / 未证实的负面信息。
- **用户补充优先**：用户贴来的面经/公司资料 > AI 搜到的结果（用户纠正 > 一切）。

### Step 3：定制出题

- **动作**：按 `21-出题规则.md` 从 5 个来源生成题库（定制简历 → 母版细节 → JD 必须项 → 缺口清单 → 行业情报），分「普通面题库」「压力面题库」两版（同题不同问法）。
- **验收**：每题能说出出处（简历哪条 / JD 哪条 / 情报哪条）；单场 8-12 主题 + 每主题 2-3 层追问弹药；**模块覆盖**：①③④⑤⑥⑧ 必保，⑦ 可 0 题；时长不足时可按 `21-出题规则.md` 注 3 的裁剪优先级裁剪（含 ② 经历深挖），但**必须在题库头部显式声明裁了哪块、为什么**，不得静默省略。
- **产出**：`[面试]\题库\题库_公司_岗位_YYYYMMDD.md`。

### Step 3.5：讲稿生成（可选，承接 定制阶段 暂缓项「项目叙事重构/面试讲稿」）

- **时机**：出题完成后；或复盘后发现「记忆模糊」类薄弱点时补。
- **动作**：对核心经历/项目按固定结构生成 1 页讲稿：`开场句 → 背景与问题 → 我做了什么 → 结果 → 与岗位的连接`，结尾附 2-3 条「可能追问 + 应对要点」。
- **数据源**：只从母版取材；母版缺细节的段落标注「待补」，不编。
- **产出**：`[面试]\讲稿\讲稿_公司_岗位_YYYYMMDD.md`；同岗复用追加。

### Step 4：模拟面试

- **动作**：
  1. 用户选人设（压力面/普通面），或由 AI 按目标岗位建议（首次面试建议普通面热手，压力面在熟悉流程后上）。
  2. 加载 `22-人设卡.md` 对应人格，**严格切换**：面试官只提问、追问、施压（压力面），不提示不评价。
  3. 按题库推进，动态追问（用户答得含糊 → 追贡献边界/数字/方法细节）。
  4. 结束时按人设收尾（普通面：询问「有什么想问我的」；压力面：冷收尾「面试结束，等待通知」），然后**切换回教练人格**，预告复盘。
- **会话协议**：用户随时可说「换压力面/换普通面/暂停/这题换掉」；换题不扣分，但不换人设前不切换人格。
- **产出**：对话实录（存 `[面试]\记录\面试_公司_岗位_YYYYMMDD_人设.md`）。
- **实时落盘（防丢失）**：每轮 Q&A 结束后立即追加实录到该文件（含面试官内心独白要点：回答关键句、追问命中点、可疑点）；面试结束只补复盘部分。禁止攒到结束一次性写。
- **群体 / AI 录制面变体**：**群面（无领导小组 LGD）**与 **AI 录制面**的方法论、角色/评分/话术、7 题框架见 `24-群面与AI面.md`，走该专项流程；单面人设与追问仍按 22 / 21。

### Step 5：复盘报告

- **动作**：按 `23-复盘规则.md` 出报告：5 维评分 + 每题点评 + 面试官内心独白 + 薄弱点归因 + 训练建议。
- **产出**：复盘报告（同一文件，追加在实录后）+ 更新 `[面试]\薄弱点库.md`。

### Step 6：演进闭环

- **动作**：
  1. 薄弱点库按「出现次数 + 根因」排序，下次面试针对性出题（跨 2+ 次面试重复的缺口 → 出训练计划）。
  2. 面试中用户答不出/答模糊的细节 → 标记「母版缺细节」→ 建议回 [档案] 挖掘记录补库（新弹药）。
  3. 面试中出现的优质措辞/新角度 → 建议回写母版（经用户确认 + 变更记录，规则同 简历阶段）。
- **产出**：更新后的薄弱点库 + 给用户的「补库建议清单」。

## 角色分工

| 角色 | 职责 |
|---|---|
| 用户 | 提供/确认 JD 与情报、选人设、回答问题、喊停/换人设、确认复盘结论 |
| AI（面试官人格） | 出题、提问、追问、施压/引导、收尾（仅面试阶段） |
| AI（教练人格） | 情报搜集、出题、复盘、薄弱点库维护、补库建议（面试外阶段） |

## 变更规则

- 复盘报告是独立产物，不改母版；补库/回写须经用户确认 + [档案] 变更记录。
- 同岗二次模拟：复用 `[面试]\题库\` 旧题库，按薄弱点库 + 新情报增量出新题，不重复全套。
