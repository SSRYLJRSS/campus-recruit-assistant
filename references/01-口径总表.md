## 二、单点权威的几个关键纪律

1. **数字只写一处**：字数、密度、权重、页数等只在对应领域文件里出现；其他文件要提就写"见 X"。
2. **SKILL.md 允许保留 6 条红线摘要**（每次必读的硬约束），但摘要后必须标权威指针，改数字时两边同步、以领域文件为准。
3. **清单只有一份**：任何"再补一份 checklist"的冲动都违反本表，改 `44-自检清单.md`。
4. **冲突处理**：两份文件打架 → 以本表指定权威为准 → 本表没覆盖 → **问用户，禁止自行选一个**。

## 二之二、配置层与规则的覆盖关系

```
用户当场指令 > config.overrides > profiles/<profile>.md > references 默认值
```

- **references 是默认值**，写了也不代表不可改；它假设"校招中文通用岗"。
- **profiles 是工作流差异整档**，切档等于换一套结构/篇幅/取舍规则。
- **config.overrides 是个人微调**，只写与 profile 不同的项。
- **不可覆盖**：五条铁律、`44-自检清单.md` 全部勾选项、真实性红线。
- 配置怎么初始化、有哪些字段、怎么重跑 → `00-首次使用与配置.md`。
- 技能内**不得出现**：绝对路径、真实姓名/学校/手机/邮箱。身份字段一律从 `[档案]` 取。

## 三、个人字段与偏好（不代判，缺失标"待补充"）

| 项 | 取值来源 | 规则 |
|---|---|---|
| 姓名/学校/专业/毕业年份 | `config.identity` 或 `[档案]\01_个人信息.md` | 只用于头部与命名；缺失标待补充，不猜测 |
| 期望薪资 | 用户提供 | 未提供时用区间式（跨度 20-30%）并标"待确认" |
| 求职邮箱 | 用户常用邮箱 | 缺失就留空并提示补充，不替用户编造 |
| 成绩排名 | `[档案]\02_教育背景.md` | 排名靠后（如后 50%）一律不写 GPA 与排名 |
| 技能熟练度 | `[档案]` 真实使用记录 | 只用真实用过的技能，不凭感觉标"熟练/精通" |
