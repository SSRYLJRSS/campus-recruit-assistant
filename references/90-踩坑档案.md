## 一、输出文件与排版事故

- **（仅当用户模板自带证件照/装饰时）复刻必带**：HTML 复刻用户模板前，先 `zipfile` 检查 `word/media/`（大文件 jpeg 多为证件照）与页眉页脚 svg；漏照片/装饰 = 「长得不一样」被打回。照片提取 → base64 内嵌（尺寸按 `wp:extent` EMU÷914400×2.54=cm）。默认档案不放假证件照（见 `40-格式红线.md` §3），此处仅针对用户自带照片的模板。
- **输出文件被占用**：用户用 WPS/查看器开着 PDF 时覆盖失败（PermissionError / Device busy）→ 改存新文件名交付 + 提示用户关闭后可清理；不要反复重试覆盖同一路径。
- **1 页铁律执行细节（2026-08-03 用户纠正「我只要1页，你这都两页了」）**：pandoc→HTML **必须带自定义 CSS**——字号/边距一律以 `40-格式红线.md` §3 为准、行距 1.2-1.3、段间距紧凑；不带 CSS 时 Edge 打印默认样式必溢出 2 页。生成 PDF 后**必须验证页数**：`python -c "import re;d=open('<pdf>','rb').read();print(re.findall(rb'/Count (\d+)',d))"`，`/Count`=1 才通过；超页先调 CSS 再砍内容（加一砍一），别只靠缩字号。
- **证件照事故（2026-08-03）**：HTML 复刻漏照片，用户反馈「你这个和我长得明显不一样啊」当场打回。
- **文件被占用时**：改存新文件名（如 `_照片版.pdf`）交付，别反复重试。

## 二、python-docx / docxtpl 技术坑

- **python-docx 模板填充三个坑**：①段落定位用文字前缀 `find()`，**绝不用列表索引**——插入/删除后索引全变，会错位删错段；②`insert_after` 返回新 Paragraph，链式使用（插完用返回值继续插），同一参考点重复 addnext 会逆序；③`next_p` 必须支持 `skip_empty` 跳过空段落（模板里条目间有空段，直接 getnext 会拿到空段导致删错/插错）。另注意 `_p` 属性只在 Paragraph 上有，CT_P 对象要兼容处理（`hasattr(p,'_p')`）。
- **docxtpl 改造/渲染四坑（2026-08-11 实测）**：①模板多个段落同前缀（如三个「开始时间-结束时间」时间行）时 find() 必误命中第一个——改造前先 `find_all()` 收集全部分组再按序赋值；②python-docx/docxtpl **不吃 MSYS 路径**（`/f/`、`/tmp/` 报 PackageNotFoundError），必须 Windows 原生路径（`C:\...`）或 `cmd //c` 转换；③占位符必须独占单 run——用 set_text 整段合并为单 run 保留首 run 样式，否则 WPS 拆 run 渲染异常；④docxtpl 不参与排版，**1 页压版靠内容长度**：模板容量约 40 段，每条描述 ≤2 行（55-70 字）、自我评价单行，超页先压缩文本别动模板（压缩公式：删括号内解释、删并列示例、数字保留）。
- **docx 保真度验证法**：`zipfile` 解包对比模板与产物的每个部件 md5——styles/header/footer/media/theme 全部一致、仅 document.xml（正文）+ core.xml（时间戳）变化 = 保真通过（实测样本 33/35）；脚本见 scripts/docx-fidelity-check.py。另用 pymupdf 检查 PDF 页数与末块 y 坐标（页面高 841.9pt，末块 y≈792 已近满页，超了必砍内容）。
- **修正用户排版 docx 内的文本**：用 python-docx run 级替换（`r.text = r.text.replace(old, new)`）保留证件照/页眉页脚/样式，先探测目标段落的 run 结构（文本可能拆在多个 run），改完重开 docx 验证旧文本无残留、新文本在。脚本：scripts/docx-run-replace.py。
- **WPS COM 自动化（历史备选，非必需）**：当前 scripts 以 `docxtpl` 出 docx + `pymupdf` 校验为主；如需 WPS 转 PDF 再用此招：`Dispatch('Kwps.Application')`（**不是** `wps.Application`，后者报「无效的类字符串」）+ `Documents.Open(src, ReadOnly=True)` + `ExportAsFixedFormat(out, 17)` 即出 PDF。曾误判「WPS 个人版 COM 不可用」，实为 ProgID 用错。

## 三、Markdown 编辑坑

- **V4A patch 改表格会吞字符**：行首 `|` 吞掉/翻倍（`|`→`||`、`||`→`|||`），反斜杠翻倍（`\`→`\\`）。43-输出与台账.md 与 05_技能库.md 各踩一次。改表格行一律用 **replace mode 单行精确替换**，改完 grep 检查 `||` 与 `\\\\` 残留。
- **参考列表必须与实际文件同步**：新增 references 后同步更新文末「参考」清单（2026-08-18 曾漏 简历改写外部调研.md / resume-template-guide.md）。

## 四、事实核实与诚实红线

- **外部可验证事实入库前先 API 核实**：用户给 GitHub 链接 → `curl api.github.com/repos/<owner>/<repo>` + `/readme` + `/languages` + `/contents` 四连。**owner 名不确定时用 `api.github.com/search/repositories?q=<name>+in:name&sort=stars` 反查**（docx-js→dolanmiu/docx、docxtemplater→open-xml-templating 均靠此定位）；GitHub 网页被反爬时改抓 `raw.githubusercontent.com/<owner>/<repo>/<branch>/README.md`。star 少如实标注「小项目」；README 声称的功能可作 bullet 依据，但「我写了测试/CI」这类归属判断要保守（目录存在 ≠ 用户亲写）。
- **技能档位升级需主导成果佐证**（编程 vibe coding 入门→精通 = 独立开源项目）。**没实际用过的技能不许标"熟练"**，面试会被追问翻车。
- **语音/口述弹药二次确认**：用户口述补充经历（语音转写常错，如「我住到」=「我主导」）时，关键归属词（主导/参与/负责/跟投）、数字、时间必须**显式复述确认后再入库**。
- **挖掘时用户说团队成果，必须追问"你具体做了哪部分"**，防止把团队成果写成个人贡献。
- 模板里的示例数字（张三、GPA 3.6 等）是**占位符**，录入时全部覆盖。

## 五、时间线与一致性

- **时间线一致性校验（投递前必查）**：多段经历同上简历前交叉检查日期重叠——两段实习重叠 = HR/背调必问。迅行出行事故：用户最终版衡广文化写 2025.6-2026.9 与星屿传媒 2026.5-8 重叠 4 个月，确认系笔误修正回 2025.9。发现矛盾先 clarify 确认再改，别替用户假设。
- **自评不得引用正文没有的东西**：2026-09-04 发现 ToC 版自评写「执行力与抗压能力经省级赛事验证」，正文无排球经历 = 悬空引用，HR 一问穿帮。此类自评与正文的交叉引用必须逐条核对。

## 六、跨域定制

- **原赛道技能 = 噪音**：母版以新媒体/内容/销售弹药为主，投政策/项目管理/科技管理类岗时必须**果断砍掉**达芬奇调色、爆款文案、广告脚本、自媒体接单等强标签，只保留可迁移底层能力（流程、对外协调、数据复盘、项目全流程、从 0 到 1）。
- **无证据硬技能绝不写经历段**：JD 要求但母版无证据 → 列入缺口清单，面试前补课，简历一律不写。
- **投 To B 技术销售/云商务岗用「技术×商务双栖」画像（2026-08-17 案例）**：技术项目（能听懂客户技术需求）+ 商务经历（直销+渠道）+ 主动出击型经历（商机挖掘人格）；弃内容岗噪音；**无云实战经验绝不写进简历**。完整知识库见 `references/31-岗位-云销售ToB.md`。
- **跨域到金融/国际化岗的迁移表达**：泛财经供稿 →「面向百万粉财经账号持续供稿，具备金融内容敏感度」（相邻迁移，绝不写「金融产品经验」）；英语如实写 CET-4 不写「流利」。完整范例见 references/19-跨域案例.md。

## 七、打分与决策

- **打分规则以 `12-匹配评分.md` 为唯一权威**，本节只留历史经验。**双口径稳健性参考（非独立规则）**：某项必须项在部分命中与 0 之间摇摆（如「英语流利」vs 母版仅 CET-4），可并列输出两口径：口径一=部分命中计入；口径二=按硬筛线判 0 → 触发「任一条必须项=0 封顶 75%」。**决策按 12**：区间中值 ≥70% 深投、50-70% 可投提示缺口、下限 <50% 强制跳过。案例（化名）：某产品助理口径一 80%、口径二 75%，可投但英语为命门。
- **JD 缺公司名/关键信息时：分析先行、落盘等确认**：JD 文本没给公司名就先完成分析在对话呈现，一次问清再落盘，别用占位名抢写文件。

## 八、流程与协作

- **SOP 用子代理模拟执行检验**：构造模拟 JD + 埋坑母版，派「严格执行者」子代理跑全流程，能挖出规则空白。模拟产物放工作区 simulation/，不污染数据层。
