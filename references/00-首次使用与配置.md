# 首次使用与配置

> **缺配置是正常的首次状态，不是错误。** 不要向用户报错，直接进入初始化。
> 触发条件（任一即可）：`config.json` 不存在 / 用户说"配置""初始化""换个目录""改规则" / 数据目录不可写。

## 一、初始化四问（用 AskUserQuestion，不要让用户手写 JSON）

问之前先做环境探测，把能猜到的作为默认选项：

| 探测 | 用途 |
|---|---|
| 当前目录、用户主目录下是否已有 `求职`/`job`/`resume` 类目录 | 猜数据根目录默认值 |
| 是否存在已有数据目录（含 `00_档案` 或 `01_JD库`）| 提供"接续已有库"选项 |
| `[档案]` 是否已有母版数据 | 决定是新建库还是接续 |

**问题 1｜数据存在哪**（最关键，必须问）

- 默认给：`<用户主目录>/recruit-data`
- 允许其他答案（自填任意绝对路径）
- 说明写清：**这里存你的母版简历、JD 分析、定制简历、面试记录；选一个会长期保留、会被备份的目录**

**问题 2｜走哪条工作流**（决定规则档，见 `profiles/`）

- `campus-cn` 校招·中文（默认）：单页、无求职意向、无技能段
- `campus-tech` 校招·技术岗：允许技能段、1-2 页、技术项目全启用
- `intern-cn` 实习：突出课程与校园项目，篇幅单页

**问题 3｜个人固定信息**（只在用到时问，不强制）

- 姓名、学校、专业、毕业年份 —— 只用于简历头部与文件命名
- **可以跳过**，后续在 `[档案]\01_个人信息.md` 补

**问题 4｜质量门严格度**（见 `46-质检与复审.md`）

- `standard`（默认）：复审最多 2 轮，门槛 8/10，跑视角 1+2+3
- `strict`：复审最多 3 轮，门槛 9/10，加跑"面试官追问"视角（视角 4）
- `off`：只跑 `44-自检清单.md`，不做换视角复审
- 轮数/门槛的唯一权威见 `46-质检与复审.md`

## 二、初始化动作（按序执行）

1. **建目录骨架**（在用户选的 `dataRoot` 下）：
   ```
   00_档案\{模板,原始材料,挖掘记录,snapshots,归档}
   01_JD库\  02_定制简历\  03_投递台账\  04_面试\{情报,题库,讲稿,记录}
   ```
2. **写 `config.json`**（放技能根目录；模板见 `config.example.json`）。
3. **回显确认**：把写入的配置**摘要成一张表**给用户看（数据目录 / 工作流 / 质量门 / 是否迁移），让用户确认或改。
4. **迁移（可选）**：用户说有旧数据 → 先 `cp -r` 整盘备份到 `<dataRoot>\_迁移备份_YYYYMMDD\`，再按 `01-口径总表.md` 第四节对照表搬，搬完核对文件数一致才删旧目录。
5. **进主流程**：初始化完成后接着办用户原本要办的事，不要停在"配置好了"。

## 三、config.json 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | ✅ | 固定 `1`，升级时用于迁移 |
| `dataRoot` | ✅ | 数据根目录绝对路径（Windows 用 `\\` 或 `/`） |
| `profile` | ✅ | `campus-cn` / `campus-tech` / `intern-cn` |
| `setupDate` | ✅ | 初始化日期 |
| `identity` | — | name / school / major / gradYear，可空 |
| `qualityGate` | — | `standard` / `strict` / `off`，默认 standard |
| `overrides` | — | 覆盖规则档的任意变量，见第四节 |

**只存稳定信息**：不要把"当前在投哪些岗""简历改到第几版"写进 config，那些属于数据层。

## 四、规则覆盖优先级（从高到低）

```
用户当场指令  >  config.overrides  >  profiles/<profile>.md  >  references 默认值
```

- `references` 里写的规则是**默认值**，假设"大多数校招中文场景"。
- `profiles/<profile>.md` 是**整套工作流差异**（结构、篇幅、模块取舍）。
- `config.overrides` 是**个人微调**，只写与 profile 不同的项，例如：
  ```json
  { "overrides": { "resume": { "selfEvalRange": [130, 160], "maxPages": 2 } } }
  ```
- 三者冲突时，上面的赢。**但 `44-自检清单.md` 与铁律（真实性/用户纠正/母版唯一）不可被覆盖。**

## 五、可覆盖 vs 不可覆盖

| 可覆盖（个人/工作流差异） | 不可覆盖（底线） |
|---|---|
| 结构模板、是否设技能段、是否写求职意向 | 真实性：不编造经历/数字/证书 |
| 自我评价字数区间与句式 | 母版唯一事实源 |
| 页数、字体、配色 | 用户纠正优先 |
| 技术项目启用档位 | 缺料必须标"缺口"，不得硬填 |
| 质量门严格度、复审轮数 | 自检清单必须全部走完 |
| 语言（中文/英文简历） | — |

## 六、重跑与修改

- 用户说"改配置""换目录""这个规则不对" → **重跑初始化**，把当前值作为默认答案，只改被问到的项。
- 手工改 `config.json` 后，让 AI 重新读取并回显一次，避免口径不一致。
- 数据目录搬家：改 `dataRoot` 前先整盘复制，改完核对 `00_档案` 文件数一致。

## 七、分享给别人时

本技能**不含**任何个人真实信息。所有真实主体都已匿名化，分三层处理：

| 类型 | 处理方式 | 示例 |
|---|---|---|
| 姓名 / 手机 / 邮箱 / 学校 / 专业 | 占位符，实际值从 `[档案]` 或 `config.identity` 取 | `<姓名>`、`<学校>` |
| 实习公司 / 个人项目 / 投递目标公司 | **一律化名**，不指向任何真实主体 | 星屿传媒、TeaBox、迅行出行 |
| 案例里的业绩数字 | 示例值，仅示范"怎么量化表达"，必须换成自己的真实数字 | 月产 10+ 篇、150 万+ |

使用纪律：

- 简历内容一律从 `[档案]` 取，**不从 references 取**。
- 案例只学**思考方式**——选什么、弃什么、怎么迁移措辞；**不抄事实**。
- **化名与真名的对照关系不写在技能内**，只在作者本地维护。新增案例时必须沿用已有化名，不得新造，否则下一代读者会认为是两家不同公司。
- `scripts/check-skill.py` 的 PII/真名检查项会把真实雇主与目标公司名判为 FAIL，改文件后跑一遍确认没有回退。

`config.json` 是使用者本地私有文件，**分享技能时不要带上它**（里面可能有真实姓名与学校）。分发只发 `config.example.json`，收到的人第一次运行会自动生成自己的配置。
