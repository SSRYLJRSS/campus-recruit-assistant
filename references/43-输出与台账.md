# 输出与版本规范

> 用途：Step 6 输出 MD（2026-08-03 起仅 MD）、命名、归档、回写规则、投递动作建议。
> 通用命名规则沿用 `references/25-面试命名.md`，本文件只定义 定制阶段 特有部分 + 修正归档位置。

## 一、产出物清单（每次定制一套，全部存数据层）

| 产出物 | 位置 | 命名 |
|---|---|---|
| JD 分析 | `[JDK]\` | `JD_公司_岗位_YYYYMMDD.md` |
| 定制简历 MD（全信息源，**唯一默认产物**，2026-08-03 起） | `[定制]\` | `CV_公司_岗位_YYYYMMDD.md` |
| 定制说明（选/弃/改/缺口） | `[定制]\` | `定制说明_公司_岗位_YYYYMMDD.md` |

- 同名多版：加 `_v2`、`_v3`，**永不覆盖旧版**。
- 归档位置修正：定制简历统一归档到 `[定制]\`，**[档案]\06_归档\ 不再存放定制简历**（原规范已同步修正）。

## 二、JD 分析存档（[JDK]\）

- 一份 JD 一份文件：JD 原文（或链接+摘要）+ 按 `01_JD分析模板.md` 的结构化分析 + Step 2 打分表 + Step 3 决策。
- 命名：`JD_公司_岗位_YYYYMMDD.md`（公司/岗位用中文，与 CV 命名一致）。
- **同岗复用**：同一岗位二次投递/改 JD → 先读旧存档，只分析差异，不重复全量。
- 一司多岗：每岗位一份文件，文件名区分岗位。

## 三、定制简历（[定制]\）

### MD 版（源格式，人机可读）

结构、分点格式、字数、字体参数**一律见 `40-格式红线.md`**，本文件不重复定义（曾因两处各写一份，导致分点排版与字数口径两轮漂移）。本文件只管：产出什么文件、叫什么名、放哪个目录、怎么回写、台账怎么记。

- 内容 = 母版挑选重构后的结果（见 `14-改写规则.md`），可追溯。
- 文件头注释块：`> 母版快照: 20260802 / 依据 JD: JD_公司_岗位_日期 / 匹配度: XX-XX%`，保证版本可回溯。

### 可选转换（默认不输出，2026-08-03 用户决定仅 MD）
- **DOCX/PDF 由用户自行转换**：WPS/Word 打开 MD 或粘贴后另存为对应格式（用户本机已装 WPS；模板样式以用户自有 docx 为准，AI 不再复刻排版）。
- 如用户明确要求 AI 生成：DOCX 用 pandoc（本机 3.10 已验证中文）；PDF 用 pandoc→HTML + Edge headless 打印（本机已验证 1 页中文渲染）。xelatex/LibreOffice/Word 本机未装，勿作主路线。
- 投递格式建议：PDF 优先（排版不跑偏）；文件名 `姓名-岗位-届别.pdf`。

## 四、定制说明（每次必须随附）

内容固定 4 块，写给用户看：
1. **选了哪些**：经历/项目/bullet 清单 + 为什么（贴 JD 哪条需求）
2. **弃了哪些**：被砍的内容 + 理由（相关度低/无量化/篇幅）
3. **改了什么**：措辞调整点（关键词替换、动词升级、顺序调整）——不含新增事实；若新增事实，注明「已回写母版」
4. **缺口清单**：Step 3 的缺口 + 补法（回母版挖掘 / 如实放弃）

> 附：可选「讲稿要点」——每条核心经历一句话讲法（为后期面试讲稿留接口，决策 8）。

## 五、回写母版规则（Step 6 可选）

- 触发条件：定制中发现**新事实**（新数字、新项目、更好的量化表述）且用户确认 → 回写母版对应文件，并在 `[档案]\变更记录.md` 记一行（时间/动作/对象/原因）。
- 不触发：仅措辞调整、关键词替换、顺序调整——这些属于「定制产物」，不污染母版。
- 定制版本身永远不因回写而改动（版本独立）。

## 六、投递状态与台账（[台账].md，2026-08-18 起每单强制维护）

- **强制建台账**（2026-08-18 修正：不再"批量时启用"，高密度投递期无台账 = 状态失控）：每单定制落盘后，**必须**在数据层 `[台账]\` 建当日台账文件 `投递记录_YYYYMM.md`（按月汇总）。首次投递前若目录不存在，先建目录+写入模板。
- 台账内容（每单一行，可 Markdown 表格）：

| 字段 | 示例 |
|---|---|
| 日期 | 2026-08-18 |
| 公司/岗位 | 泰盛软件 / 需求分析师 |
| JD 存档 | JD_<公司>_需求分析师_20260818.md |
| 匹配区间 | 76-84%（口径一）/ 68-75%（口径二） |
| 状态 | 待投 → 已投 → 面试中 → Offer / 拒绝 |
| 待办补课 | 计算机专业口径话术 / Visio 演示 / 泰盛产品线功课 |

- **单份投递状态同步记在定制简历文件名后缀**（`_已投` / `_面试中` / `_拿到Offer`，沿用 [档案] 命名规范），台账为主、文件名后缀为辅。投递状态变更（进面/拒信/Offer）时**两处同步更新**。
- 用户自行投递后反馈状态时，AI 负责回写台账（用户说"投了"/"进面了"/"拒了"即触发）。

## 七、投递动作规范（2026-08-03 新增；MD 交付后，PDF/DOCX 由用户自行转换，本规范对投递动作通用）

| 动作 | 规则 |
|---|---|
| 文件名 | `<姓名>-<岗位>-<届别>.pdf`（大厂可加院校：`<姓名>-<岗位>-<届别>.pdf`）；绝不用「简历.pdf」「最终版2」；转换后检查命名 |
| 邮件标题 | `【岗位】<姓名>+亮点`（例：【数据分析】<姓名>·统筹 80+ 场活动）；内推注明；不用 Re:/Fw: |
| 邮件正文 | 不空白：称呼 + 一句话匹配点 + 附件说明 + 联系方式；手机端阅读，勿长篇 |
| 附件 | 只附 PDF 简历；不用压缩包/图片版（无法复制、易被拦截） |
| 发件人 | 真实姓名，不用个性昵称 |
| 检查 | 投递前打开附件预览；最后填收件人防误发 |
